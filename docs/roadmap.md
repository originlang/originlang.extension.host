# Host 实施路线图

更新日期：2026-11-04。本文是计划，不代表已完成实现或验证。职责以仓库根 `AGENTS.md` 为准。

## 目标

交付可独立下载和运行的扩展宿主服务。CLI 与 HomeWorld 均为可选消费者，不将 Host 运行引擎编译进自身；harness 由本服务动态加载。

## 实施顺序

1. 编写服务协议与发布清单规范：入口名称、启动参数、配置与数据目录、协议协商、就绪检查、错误、能力查询、平台产物、校验及 ABI 兼容范围。
   - 服务契约已起草：[docs/service-contract.md](service-contract.md)（H01，状态待验证）。它固定入口 `oext-host`、参数与配置优先级、按根目录隔离的实例、`host.hello` 版本协商、错误码与退出码；第 12 节列出当前实现缺口。
   - 发布清单与包结构属 H02，尚未编写。
2. 将 CLI 中的宿主装配、服务入口与服务端传输迁入本项目；本地优先 stdio，保留现有网络鉴权。
3. 发布独立服务与兼容的 `oext-sandbox`；harness 保持单独发布，不作为服务启动前提。
4. 提供扩展安装、授权、启停、状态与日志的稳定协议，供两种消费者适配。
5. 为 harness 的任务事件与取消提供所需宿主能力，避免将 agent 循环引入宿主。

## 验收标准

- 不安装 CLI 或 HomeWorld 即可启动、报告版本及能力、接受请求并退出。
- stdio 协议不混入日志；EOF 和正常关闭触发清理，异常有明确错误。
- 发布清单准确描述平台、校验、协议、插件 ABI 与沙箱版本关系。
- 客户端只能管理自己拥有的实例，连接已有实例不隐含停止或升级权限。

## 当前差距与不做事项

当前服务入口仍在 CLI，独立 Host 服务与发布链待迁移。服务名称和新命令格式应由契约确定，不在消费者里猜测。

暂不引入自动服务发现、跨机器调度或自动共享实例。当前仅编写代码和文档，验收执行与发布待用户要求。
